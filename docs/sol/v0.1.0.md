# SOL Editor v0.1.0

Status: release

## Objective

Deliver a reproducible E1M1 graybox, classic Doom progression, guided local
setup, and one locked visual/audio wadpack shared by engine and editor authoring
and test paths.

## Included

- Fourteen connected E1M1 areas and 176 staged monster placements.
- Deterministic generation, PWAD validation, packaging, and launch commands.
- Midnight Commander setup for repositories, IWAD, and local toolchain.
- Eighteen-entry wadpack manifest under wadpack contract 2.
- Source-hash validation, archive normalization, runtime hashing, and tamper detection.
- Mandatory wadpack injection into `sol-play`.
- Automatic locked-resource injection into the SOL Editor authoring data set.
- Automatic `sol-edit` routing through `tools/sol-editor-engine.sh` for editor tests.
- Local-only third-party storage under sibling `vend/wadpack`.
- Shared SOL application icon and repaired inherited CI.
- Final `0.1.0` metadata and `sol-e1m1-v0.1.0.pk3` package identity.

The original fourteen-resource presentation stack is retained in positions 1–14.
Contract 2 appends Universal Ambience, CosmoAmbience Script edited, Ambient
decorations, and TargetSpy v3.1.0 as entries 15–18.

## Release checks

1. E1M1 generation and structural validation are deterministic.
2. The map contains the normal Doom exit required for statistics and Episode 1 world-map progression.
3. The wadpack importer recognizes and normalizes every required source form.
4. Runtime paths are emitted in the exact eighteen-entry order.
5. Changed or missing runtime files block launch.
6. `sol-play` rebuilds the current engine runtime and injects the locked pack.
7. `sol-edit` loads the same locked resources into the editor for authoring without persisting them over the user's normal resource configuration.
8. Editor map tests route through the locked wrapper without persisting over the user's normal test-engine setting or duplicating the authoring resources on the command line.
9. Public commits contain no third-party WAD/PK3 binaries.
10. Linux, Windows, Flatpak, and SOL workflows complete successfully.
11. Release metadata, generated map statistics, wadpack metadata, and package naming agree on `0.1.0`.
12. CI asserts wadpack contract 2, eighteen entries, and the exact four appended resource IDs/runtime names.

## Local deployment requirement

The eighteen third-party resources are deliberately not redistributed by this
repository. A local SOL installation is considered launch-ready only after the
wadpack importer verifies all eighteen entries and their runtime hashes.

`HQPSXMUS.WAD.zip` remains part of the approved configuration. Setup reports it
as missing and blocks normal SOL launches until it is supplied locally. A
complete local gameplay pass remains a machine-level verification step after all
required files are installed; it is not replaced by source-level CI.
