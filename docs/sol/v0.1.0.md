# SOL Editor v0.1.0

Status: release

## Objective

Deliver a reproducible E1M1 graybox, classic Doom progression, guided local
setup, and one locked visual/audio wadpack shared by engine and editor authoring
and test paths.

## Included

- Fourteen connected E1M1 areas and 176 staged monster placements.
- Deterministic generation, PWAD validation, packaging, and launch commands.
- Midnight Commander setup for repositories, IWAD, and local toolchain.
- Eighteen-entry wadpack manifest under wadpack contract 2.
- Source-hash validation, archive normalization, runtime hashing, and tamper detection.
- Bundle contract 1 with the complete local runtime stored in `sol.pk3`.
- Eighteen intact embedded third-party WAD/PK3 components followed by SOL runtime and E1M1 content components.
- `SOLPACK.json` component hashes and embedded `THIRD_PARTY.md` attribution.
- Automatic materialization/mounting of the bundle for `sol-play`, `sol-edit`, and editor tests.
- The same `sol.pk3` copied into local engine and editor package/build directories.
- Shared SOL application icon and inherited Linux/Windows/Flatpak CI.

The original fourteen-resource presentation stack is retained in positions 1–14.
Wadpack contract 2 appends Universal Ambience, CosmoAmbience Script edited,
Ambient decorations, and TargetSpy v3.1.0 as entries 15–18.

The physical bundle order is:

```text
01–18  locked third-party resources
19     SOL runtime component
20     SOL E1M1 content component
```

## Runtime behavior

The final local package is `build/sol/sol.pk3`. It is a container bundle rather
than a flattened mod archive. Each upstream resource stays intact under
`components/`, preventing root-level files such as `ZSCRIPT`, `MAPINFO`,
`DECORATE`, `MENUDEF`, sprites, and sounds from overwriting one another during
packaging.

`sol-play` verifies `sol.pk3`, materializes all twenty components into a cache
keyed by the bundle hash, and mounts them in order. `sol-edit` materializes the
eighteen third-party resources for authoring. UDB tests use the first nineteen
components, followed by UDB's temporary map.

After `sol.pk3` has been built, the loose normalized wadpack is no longer a
runtime dependency. It remains the source used to regenerate the bundle.

## Release checks

1. E1M1 generation and structural validation are deterministic.
2. The map contains the normal Doom exit required for statistics and Episode 1 world-map progression.
3. The wadpack importer recognizes and normalizes every required source form.
4. Wadpack contract 2 contains exactly eighteen ordered entries.
5. Bundle contract 1 contains exactly the expected third-party, runtime, and content components.
6. Every embedded component is SHA-256 verified before materialization.
7. A repeated synthetic bundle build is byte-for-byte deterministic.
8. `sol-play` mounts bundle entries 1–20 in order.
9. `sol-edit` exposes entries 1–18 to authoring without rewriting normal UDB resources.
10. Editor map tests mount entries 1–19 and allow UDB's temporary map to follow.
11. `THIRD_PARTY.md` is included in source and inside `sol.pk3`.
12. Public commits contain no third-party WAD/PK3 binaries.
13. Release metadata agrees on v0.1.0, wadpack contract 2, and bundle contract 1.

## Attribution and deployment boundary

The repository now records accreditation/provenance in `THIRD_PARTY.md`, and the
bundle preserves any notices contained in each upstream archive. This does not
relicense third-party content or independently create redistribution permission.

Several resources remain `review-required`; HQ PlayStation music and sound
effects remain recorded as local-only proprietary audio. Accordingly, the full
`sol.pk3` may be built and included in local SOL engine/editor packages for
development and testing, but is not yet cleared for a public binary release.
