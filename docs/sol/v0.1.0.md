# SOL Editor v0.1.0

Status: release

## Objective

Deliver a reproducible E1M1 graybox, classic Doom progression, guided local
setup, and one locked presentation wadpack shared by engine/editor authoring and
test paths.

## Included

- Fourteen connected E1M1 areas and 176 staged monster placements.
- Deterministic generation, PWAD validation, packaging, and launch commands.
- Midnight Commander setup for repositories, IWAD, and local toolchain.
- Eighteen-entry wadpack manifest under wadpack contract 2.
- Source-hash validation, archive normalization, runtime hashing, and tamper detection.
- Bundle contract 1 with the complete local runtime stored in `sol.pk3`.
- Eighteen intact third-party WAD/PK3 components followed by SOL runtime and E1M1 content components.
- Root-level numbered `.wad` carriers that activate UZDoom's native embedded-resource loader.
- One-file gameplay/test launch through `-file sol.pk3`.
- `SOLPACK.json` component hashes and embedded `THIRD_PARTY.md` attribution/provenance.
- UDB-only materialization of entries 1–18 for authoring-resource access.
- The same `sol.pk3` copied into local engine and editor package/build directories.
- A self-contained `sol-engine` launcher installed beside locally built UZDoom.

The original fourteen-resource presentation stack is retained in positions 1–14.
Wadpack contract 2 appends Universal Ambience, CosmoAmbience Script edited,
Ambient decorations, and TargetSpy v3.1.0 as entries 15–18.

The physical bundle order is:

```text
01–18  locked third-party resources
19     SOL runtime component
20     SOL E1M1 content component
```

## Runtime behavior

The final local package is `build/sol/sol.pk3`. It is not a flattened mod
namespace. Each source archive remains byte-for-byte intact inside a numbered
root-level `.wad` carrier such as `01-voxel-doom.wad` or
`19-sol-runtime.wad`.

The carrier suffix is not a format conversion. UZDoom's existing filesystem
recognizes root-level `.wad` members as embedded resources, opens each member by
its actual content, and recursively mounts the numbered carriers in lexical
order. `sol-play` and editor playtests therefore pass only `sol.pk3` as the SOL
resource file.

This preserves conflicting root files such as `ZSCRIPT`, `MAPINFO`, `DECORATE`,
`MENUDEF`, sprites, and sounds until UZDoom applies the intended ordered-resource
semantics.

`sol-edit` materializes only entries 1–18 to their original normalized filenames
for UDB's authoring data set. The materialized files are not required by
playtests; the test wrapper passes the bundle first and UDB's temporary map after
it.

After `sol.pk3` has been built, the loose normalized wadpack is no longer a
normal runtime dependency. It remains the build source used to regenerate the
bundle.

## Release checks

1. E1M1 generation and structural validation are deterministic.
2. The map contains the normal Doom exit required for statistics and Episode 1 world-map progression.
3. The wadpack importer recognizes and normalizes every required source form.
4. Wadpack contract 2 contains exactly eighteen ordered entries.
5. Bundle contract 1 contains the expected third-party, runtime, and content components.
6. Every embedded carrier has a contiguous numeric order and `.wad` carrier suffix.
7. Every embedded child is SHA-256 verified, and live SOL runtime/content/credits are checked for staleness.
8. A repeated synthetic bundle build is byte-for-byte deterministic.
9. Gameplay and editor tests pass exactly one `sol.pk3` rather than eighteen loose resources.
10. UDB authoring exposes entries 1–18 without rewriting the user's normal resource configuration.
11. The self-contained package can reuse `sol.pk3` after the loose `vend` runtime is removed.
12. `THIRD_PARTY.md` is included in source and inside `sol.pk3`.
13. Public commits contain no third-party WAD/PK3 binaries.
14. Release metadata agrees on v0.1.0, wadpack contract 2, and bundle contract 1.

## Attribution and deployment boundary

The repository records accreditation/provenance in `THIRD_PARTY.md` and the
manifest. Universal Ambience's upstream distribution identifies the three
ambience components and lists the package as GPL; TargetSpy and FinalCustomDoom
publish GPL-3.0-only notices; NashGore and Voxel Doom source/creator information
is also recorded.

This inventory does not relicense third-party content or independently create
redistribution permission. The ambience package includes externally sourced
audio, the CosmoAmbience file is a supplied edited variant, several other
resources remain under review, and HQ PlayStation music/sound effects remain
local-only proprietary audio. The full `sol.pk3` may be built and included in
local SOL engine/editor packages for development and testing, but is not yet
cleared for a public binary release.
