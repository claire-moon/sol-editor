# SOL Editor v0.2.0 — story authoring foundation

Status: active development

## Objective

Define a deterministic authoring contract for map story data before E1M1 narrative content is written.

## Story contract 1

The canonical manifest is `sol-project/story/story.json`. It contains four typed namespaces:

- `events`
- `objectives`
- `subtitles`
- `radio`

IDs are integers in the inclusive range 1–65535. IDs and lowercase stable keys must be unique within each namespace. Once assigned to shipped content, IDs are append-only and must not be silently reused for a different story meaning.

Events may reference objective, subtitle, and radio IDs. `tools/sol-story.py` rejects duplicate IDs/keys, invalid identifiers, and dangling references.

The initial E1M1 manifest intentionally contains no authored story entries. Narrative text, timing, and triggers will be added only when those beats are designed.

## Packaging

`tools/sol-build.sh` validates the story manifest before building the content component and embeds the exact manifest as `SOLSTORY.json` beside `SOLINFO` and `maps/E1M1.wad`.

The content component is now `sol-e1m1-v0.2.0.pk3`. The final runtime remains `sol.pk3` under bundle contract 1, with wadpack contract 2 unchanged.

## Validation

CI validates metadata, the canonical manifest, positive and negative story fixtures, deterministic E1M1 generation, component packaging, and the corrected 18-resource `SOLINFO` metadata.
